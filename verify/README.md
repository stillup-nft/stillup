# 추첨 재현하기

333개 토큰의 배정은 고정 시드로 결정적입니다. 아래 명령으로 직접 재현해
운영자가 정점을 조작하지 않았음을 확인할 수 있습니다.

```bash
python3 build_tokens.py        # tokens.json 과 provenance.txt 를 다시 만든다
shasum -a 256 tokens.json      # 원본과 같은지 대조
```

`provenance.txt` 의 `sha256` 은 333개 토큰의 모든 메타데이터를 덮습니다 —
종·직업·시각·배경 시간대·인쇄 마감. 빠진 항목은 없습니다.

## 이 해시는 최종본입니다

컨트랙트에 `provenanceHash` 상수로 박히는 값이 이 값이며,
배포 후에는 어떤 함수로도 바꿀 수 없습니다.

## 무엇이 무작위가 아닌가

- 종마다 정확히 9장, 아홉 시간대에 하나씩 — 구조로 강제됩니다
- 333분이 333마리에 일대일 — 겹치는 분이 없습니다
- 03:33 은 홀로그램으로 고정 — 컬렉션의 정점 한 장

## 무엇이 아직 정해지지 않았는가

위 해시가 고정하는 것은 **그림 333장의 순서**입니다.
어떤 토큰 번호가 어떤 그림이 될지는 아직 정해지지 않았습니다.

```
그림 번호 = ( 토큰 번호 + offset ) mod 333
```

`offset` 은 **판매가 모두 끝난 뒤**, 미리 예약해 둔 **미래 블록의 해시**로 정해집니다.
확정 함수 `setStartingIndex()` 는 누구나 호출할 수 있고, 결과는 하나뿐입니다.
창립자 몫 세 장은 offset 이 존재하기 전인 **컨트랙트 생성자에서** 발행되므로
만든 사람도 어떤 그림을 받을지 고를 수 없습니다.
